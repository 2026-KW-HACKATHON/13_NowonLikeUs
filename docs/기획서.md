# 월계는 처음이라 — 기획서

- 작성일: 2026-09-24
- 대상: 2026 KW 해커톤 (광운대학교)
- 트랙: **배리어프리 및 생활 편의** — "이동 약자의 접근성과 주민의 일상 편의를 기술로 보완"
- 산출물: Next.js 기반 반응형 웹앱

## 1. 한 줄 정의

**월계1동에 처음 온 사람이 자기 상황에 맞는 할 일 목록을 받고, 막히면 묻고, 그 질문과 답이 다음 사람의 목록으로 쌓이는 앱.**

---

## 2. 문제 정의

> ### 외부 검증 — 정부가 같은 문제를 8일 전에 공식 인정했다
>
> **2026년 9월 16일**, 국민권익위원회가 「전입자 생활정보 사전안내 강화 방안」을 마련해 **행정안전부와 기초지방정부에 제도개선을 권고**했다.
>
> 권고 배경은 아래 2.2~2.4절에서 도출한 문제 정의와 같다 — 전입자에게 필요한 행정절차·지원사업·생활 혜택 정보가 **부서별·사업별로 분산되어 한 번에 확인하기 어렵고**, 혜택 신청 시기를 놓치는 사례가 있었다는 것이다. 정부24 온라인 전입신고 화면에 **생활정보 안내를 받을지 선택하는 절차조차 없다**는 점도 함께 지적됐다.
>
> 권고에 포함된 안내 항목에는 전입 후 확인 사항, 출산·양육·청년 등 지원사업, 대중교통·공공시설 감면, **생활폐기물 배출 정보**, 민원 문의처가 들어간다.
>
> **노원구도 이 권고의 이행 대상이다.** 이 기획은 구가 해야 할 일의 도구가 된다.
>
> **다만 이 근거는 양날이다.** "곧 정부가 하지 않겠느냐"는 질문이 따라온다. 답은 4.2절에 준비해 둔다.

### 2.1 월계1동에서는 생활 지식이 매년 리셋된다

광운대 캠퍼스가 동 안에 있어 **코호트가 계속 교체된다.** 자취생은 2~4년 살다 떠나고, 그가 쌓은 지식 — 쓰레기를 언제 어떻게 버리는지, 종량제 봉투를 어디서 파는지, 이 절차를 어디서 하는지 — 은 떠날 때 통째로 사라진다. 다음 사람은 0에서 다시 시작하고 이게 매년 반복된다.

이는 캠퍼스를 낀 동네의 구조적 문제이므로 **월계1동의 지역 문제가 맞다.**

### 2.2 진짜 문제는 "모른다는 걸 모르는 것"이다

검색은 질문을 알아야 할 수 있다. 전입신고를 14일 안에 해야 한다는 걸 **모르면 검색도 못 한다.** 에브리타임·당근 동네생활은 **물어봐야 답이 오고**, 답은 시간순으로 묻히며, 2년 전 글이 지금도 맞는지 알 수 없다.

### 2.3 정부 서비스는 "이미 알고 찾아온 사람"을 전제한다

- **국민비서 구삐**: 여권 만료·자동차검사·세금 등 알림과 전입신고 등 주민등록 사무의 **신청 결과** 안내. 알림을 받으려면 먼저 신청하고 항목을 골라야 한다. **전입신고를 한 뒤에** 결과를 알려주지, 해야 한다는 걸 먼저 알려주지 않는다.
- **정부24 원스톱 서비스 12종**: 전입신고 포함. 역시 **전입신고를 하러 온 사람**에게만 유효하다.

### 2.4 그리고 정부가 커버하는 건 "행정"이지 "생활"이 아니다

| 정부가 커버 | 아무도 커버 안 함 |
|---|---|
| 전입신고, 확정일자, 세금, 여권 | 쓰레기 배출 요일, 종량제 봉투 판매처 |
| 보조금, 자동차검사 | 분리수거·대형폐기물 규정 |
| 민원 처리 결과 | 인터넷·가스·수도 개통 |
| | 동네 병원·약국 야간 진료 |

**오른쪽은 전부 동네마다 다르다.** 노원구 쓰레기 규정은 노원구에만 해당하고, 전국 대상 앱이 다룰 수 없다.

### 2.5 기존 자취 앱은 전부 전국 단위 일반론이다

오늘의집(인테리어·자취 꿀팁), 자아도취(자취 노하우 커뮤니티), 동네형(편의점 할인), 고시원 레이더(방 검색), 자취체크(생활 관리) — 전부 **"자취 일반"**을 다루고 **동네별 실제 규정·시설은 다루지 않는다.**

## 3. 솔루션 — 핵심 순환

```
   ┌─────────────────────────────────────────────┐
   │                                             │
   ▼                                             │
[상황 입력]                                       │
주소·거주형태·계약형태·이사일                        │
   │                                             │
   ▼                                             │
[내 할 일 목록]  ◄──────────────── [승격]          │
나에게만 해당하는 것만              확인된 답이       │
   │                              정식 항목이 됨    │
   ▼                                   ▲          │
[막히면 질문] ──► [AI 답변] ──► [주민이 확인해줌] ───┘
                로컬 지식 참조
```

이 고리 하나가 제품의 전부다. 여기서 두 가지가 동시에 나온다 — **쓸수록 월계1동 로컬 지식이 쌓이고, 콜드스타트가 저절로 풀린다.**

### 3.1 개인화 축은 "시점"이 아니라 "상황"이다

이사일 기준 D+N 체크리스트는 누구에게나 같아서 그냥 블로그 글이다. 실제로는 상황에 따라 할 일이 갈린다.

| 상황 | 갈리는 할 일 |
|---|---|
| 전세 | 확정일자 최우선 — 안 받으면 보증금을 잃을 수 있음 |
| 월세 | 전입신고 + 월세 세액공제 |
| 기숙사 | 전입신고 처리 방식이 다름 |
| 원룸·빌라 | 종량제 봉투 직접 구매, 분리수거 요일 준수 |
| 아파트 | 관리사무소가 대행하는 항목이 많음 |
| 차량 보유 | 거주자 우선주차 신청 |
| 반려동물 | 동물등록 (미등록 시 과태료) |

**해당 없는 항목은 아예 보이지 않는다.** 이것이 일반 체크리스트 앱과 갈리는 지점이다.

### 3.2 할 일 하나의 구성

- **뭘 해야 하나** — 전입신고
- **안 하면 어떻게 되나** — 14일 넘기면 과태료, 보증금 보호를 못 받음
- **언제까지** — 이사일로부터 14일
- **어디서 어떻게** — 월계1동 주민센터 실주소·전화(바로 전화 걸기) 또는 정부24 링크

세 번째가 핵심이다. **"안 하면 어떻게 되는지"가 없으면 사람은 안 한다.** 대부분의 체크리스트가 이걸 빼먹는다.

### 3.3 질문이 지식이 되는 고리

```
질문 → 확인된 할 일 카드로 답 (근거 없으면 "확인 필요" 표시)
     → 살아본 사람이 답변 작성
     → 다른 주민이 "맞아요"로 확인 (큐 정렬 기준일 뿐, 승격 조건 아님)
     → 운영자 검토 큐
     → 운영자가 공식 자료로 확인 · 편집 후 정식 할 일로 승격
     → 해당 상황의 다음 사람에게 노출
```

질문할 때 **그 사람의 상황 스냅샷**(거주형태·계약형태)을 함께 저장한다. 승격 시 "이 답이 누구에게 해당하는지" 판단하는 근거가 된다. 전세 세입자가 물어 나온 답이 기숙사생에게 뜨면 안 된다.

## 4. 차별점

### 4.1 비교표

| | 정부 서비스<br>(구삐·정부24) | **이사노트**<br>(isanote.kr) | 커뮤니티<br>(에브리타임·당근) | **강화군 동네안내자** | 자취 앱<br>(오늘의집 등) | **월계는 처음이라** |
|---|---|---|---|---|---|---|
| 진입 조건 | 알고 찾아와야 함 | 이사일·유형 입력 | 물어봐야 답이 옴 | 군이 매칭해줌 | 검색해야 함 | **구역·상황만 넣으면 됨** |
| 다루는 범위 | 행정 | **행정 절차** | 잡다 | 생활 전반 | 자취 일반 | **행정 + 동네 생활** |
| 지역 단위 | 전국 동일 | **전국 공통** | 비구조화 | 강화군 12개 읍·면 | 전국 동일 | **월계1동 단위** |
| 개인화 | 없음 | **시점(D-30~D+3)** | 없음 | 사람이 판단 | 없음 | **상황별로 갈림** |
| 정보 축적 | 기관이 갱신 | 고정 | 묻히고 낡음 | **사람과 함께 사라짐** | 일반론 | **질문이 지식으로 승격** |
| 확장성 | 전국 | 전국 | 전국 | **1:1, 200회 목표** | 전국 | 대학가 복제 가능 |

**가장 가까운 것은 이사노트다.** 이사일과 이사유형(전월세·매매)만 넣으면 전입신고·확정일자·전월세신고를 D-30·D-7·D-DAY·D+3으로 자동 배치한다. 이 기획의 "상황 입력 → 할 일 목록"과 구조가 같다.

**따라서 타임라인 자체를 차별점으로 내세우면 안 된다.** 이사노트가 이미 한다. 갈리는 지점은 셋이다.

1. **동네 생활 정보** — 이사노트는 전국 공통 행정 절차만 다룬다. 쓰레기 배출 요일, 종량제 봉투 판매처처럼 동네마다 다른 것은 없다
2. **개인화 축** — 이사노트는 *시점*으로 배열하고, 이 기획은 *상황*(거주형태·계약형태·차량·반려동물)으로 분기한다
3. **축적** — 이사노트는 고정된 목록이고, 이 기획은 질문이 승격돼 목록이 자란다

### 4.2 "곧 정부가 하지 않겠느냐"에 대한 답

권익위 권고(3절)는 강력한 근거이자 동시에 반문을 부른다. 답은 권고 내용 자체에 있다.

- 권고는 **"누리집·전자책 등으로 종합 안내"** 다. 즉 **정적 안내물**이고, 상황별 분기도 질문-답변도 갱신 구조도 없다
- 권고는 **강제가 아니며** 기초지방정부가 각자 여건에 맞게 이행한다
- **노원구가 이행하려면 도구가 필요하고, 이 기획이 그 도구다**

### 4.3 강화군 사례가 뒷받침하는 것

강화군은 전입자와 주민을 **1:1로 연결하는 '동네안내자'** 를 운영 중이다. 12개 읍·면 안내자와 분야별 안내자로 구성되며, 발대식에서 주민들이 워크숍으로 **쓰레기 배출 방법·마을 규약·생활 인프라**를 담은 '슬기로운 동네생활 가이드'를 직접 작성했다. 11월까지 200회 이상 운영이 목표다.

이는 **"오래 산 주민이 참여하겠느냐"** 는 의문에 대한 실증이다. 지자체가 실제로 주민을 동원해 하고 있다.

동시에 한계도 보여준다. **1:1 오프라인은 확장되지 않고(200회 목표), 안내자가 그만두면 지식이 함께 사라진다.** 가이드는 종이로 한 번 만들고 끝이다. 이 기획은 같은 일을 **웹에서, 쌓이는 구조로** 한다.

## 5. 핵심 설계 결정

### 5.1 AI는 정보를 생성하지 않는다

행정·생활 정보는 **팀이 조사해 넣은 시드 데이터와 주민이 확인한 답변만** 사용한다. 전입신고 기한을 AI가 잘못 말하면 사용자가 **실제로 과태료를 낸다.**

AI의 역할은 셋뿐이다.
1. 질문에 맞는 할 일 카드를 로컬 지식에서 고르기 — **문장은 쓰지 않는다.** 화면 안내 문장은 서버 고정 문구이고, 근거가 없으면 "확인 필요" 표시
2. 새 질문이 기존 질문과 같은 건지 판정해 병합
3. 확인된 답변을 할 일 형식(제목/왜/언제/어디서)으로 정리한 **승격 초안** 작성

**정보의 출처는 항상 사람이다.**

### 5.2 자동 승격은 하지 않는다

확인 수는 운영자 검토 큐의 정렬 기준일 뿐이고(임계값을 두지 않는다 — 초기엔 확인이 모이지 않아 승격이 한 번도 안 일어날 수 있다) 최종 판단은 사람이 한다. 잘못된 정보가 "정식 할 일"이 되면 과태료로 돌아오기 때문이다.

### 5.3 받으러 오는 사람에겐 로그인이 없다

| 하는 일 | 로그인 |
|---|---|
| 상황 입력, 할 일 목록 보기, 완료 체크 | **불필요** (브라우저 저장) |
| 질문하기 | **불필요** — 질문은 익명이다 |
| 답변 달기, "맞아요" 누르기 | **필요** |
| 승격 (할 일 발행) | **운영자 계정** |

처음 온 사람이 회원가입부터 해야 하면 그 자체가 앱을 안 쓰는 이유가 된다. 질문은 막힌 사람이 하는 행동이라 받는 쪽에 둔다. 스팸과 책임 문제는 남들이 믿고 쓰게 되는 행동 — 답변과 확인 — 에만 걸면 충분하다.
로그인한 상태로 질문해도 질문자 닉네임은 공개 목록에 나가지 않는다(운영자 승격 큐에서만 보인다).

- 외부 기관 승인·연동 없이 독립 동작 — 민원 접수 API 같은 외부 의존을 설계에서 배제
- 운영 주체가 명확 — 동주민센터·대학 생활관·학생회 중 누구든 운영자 역할을 맡을 수 있음
- 다른 대학가로 그대로 복제 가능 (시드 데이터만 교체)
