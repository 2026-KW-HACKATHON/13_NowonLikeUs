# 월계는 처음이라

**월계1동에 처음 온 사람이 자기 상황에 맞는 할 일 목록을 받고, 막히면 묻고, 그 질문과 답이 다음 사람의 목록으로 쌓이는 웹앱.**

2026 KW 해커톤 (광운대학교) — **배리어프리 및 생활 편의** 트랙
*"이동 약자의 접근성과 주민의 일상 편의를 기술로 보완"*

> **현재 상태:** 기획·설계 완료, 구현 진행 중. 9/28 중간발표 범위는 "받는 쪽"(상황 입력 → 할 일 목록 → 상세 → 질문)이고, 질문이 지식으로 승격되는 고리는 10/8~9 본선 범위입니다.

## 풀려는 문제

**월계1동에서는 생활 지식이 매년 리셋됩니다.**

광운대 캠퍼스가 동 안에 있어 코호트가 계속 교체됩니다. 자취생은 2~4년 살다 떠나고, 그가 쌓은 지식 — 쓰레기를 언제 어떻게 버리는지, 종량제 봉투를 어디서 파는지, 이 절차를 어디서 하는지 — 은 떠날 때 통째로 사라집니다. 다음 사람은 0에서 다시 시작하고, 이게 매년 반복됩니다.

그리고 **진짜 문제는 "모른다는 걸 모르는 것"입니다.** 검색은 질문을 알아야 할 수 있습니다. 전입신고를 14일 안에 해야 한다는 걸 모르면 검색도 못 합니다.

**2026년 9월 16일, 국민권익위원회가 같은 문제를 공식 인정했습니다.** 「전입자 생활정보 사전안내 강화 방안」을 행정안전부와 기초지방정부에 권고했고, 여기엔 생활폐기물 배출 정보까지 포함됩니다. 노원구도 이행 대상입니다.

## 무엇이 다른가

| | 정부 서비스<br>(구삐·정부24) | 이사노트 | 커뮤니티<br>(에브리타임·당근) | **월계는 처음이라** |
|---|---|---|---|---|
| 진입 조건 | 알고 찾아와야 함 | 이사일·유형 입력 | 물어봐야 답이 옴 | **구역·상황만 넣으면 됨** |
| 다루는 범위 | 행정 | 행정 절차만 | 잡다 | **행정 + 동네 생활** |
| 지역 단위 | 전국 동일 | 전국 공통 | 비구조화 | **월계1동 단위** |
| 개인화 | 없음 | 시점(D-30~D+3) | 없음 | **상황별로 갈림** |
| 정보 축적 | 기관이 갱신 | 고정 | 묻히고 낡음 | **질문이 지식으로 승격** |

**개인화 축이 "시점"이 아니라 "상황"입니다.** 이사일 기준 D+N 체크리스트는 누구에게나 같아서 그냥 블로그 글입니다. 전세면 확정일자가 뜨고, 기숙사면 안 뜹니다. 차가 있으면 거주자 우선주차가 뜨고, 없으면 안 뜹니다. **해당 없는 항목은 아예 보이지 않습니다.**

## 핵심 순환

```
   ┌─────────────────────────────────────────────┐
   │                                             │
   ▼                                             │
[상황 입력]                                       │
구역·거주형태·계약형태·이사일                        │
   │                                             │
   ▼                                             │
[내 할 일 목록]  ◄──────────────── [승격]          │
나에게만 해당하는 것만              확인된 답이       │
   │                              정식 항목이 됨    │
   ▼                                   ▲          │
[막히면 질문] ──► [AI 답변] ──► [주민이 확인해줌] ───┘
                로컬 지식 참조
```

이 고리 하나가 제품의 전부입니다. 쓸수록 월계1동 로컬 지식이 쌓이고, 콜드스타트가 저절로 풀립니다.

## 설계 원칙 세 가지

**1. AI는 정보를 생성하지 않습니다.**
행정·생활 정보는 팀이 조사해 넣은 시드 데이터와 주민이 확인한 답변만 씁니다. 전입신고 기한을 AI가 잘못 말하면 사용자가 **실제로 과태료를 냅니다.** AI의 역할은 셋뿐입니다 — 로컬 지식으로 답하기, 질문 중복 판정, 승격 초안 작성. **정보의 출처는 항상 사람입니다.**

**2. 금액·기한·장소는 AI를 거치지 않습니다.**
AI 답변은 안내 문장만 담고, 구체적인 값은 DB 원문을 그대로 렌더한 카드로 붙입니다. 숫자가 AI를 통과하지 않으면 숫자는 틀리지 않습니다.

**3. 받으러 오는 사람에겐 로그인이 없습니다.**
상황 입력·할 일 목록·완료 체크는 브라우저에만 저장하고 계정을 만들지 않습니다. 처음 온 사람이 회원가입부터 해야 하면 그 자체가 앱을 안 쓰는 이유가 됩니다. 로그인은 질문·답변·확인처럼 **남기는 행동**에만 걸립니다.

그리고 **상세 주소(번지·건물명·호수)는 수집하지 않습니다.** 쓰레기 배출 요일이 갈리는 구역 단위면 기능상 충분하고, 그 이상은 쓰이지도 않으면서 개인정보 부담만 늘립니다.

## 오정보 방지 — 6층 방어

행정 정보가 틀리면 사용자가 실제로 피해를 봅니다. 한 겹으로는 부족합니다.

| 층 | 내용 |
|---|---|
| 1 · 생성 금지 | 지식에 없으면 `UNKNOWN`. 추측하지 않는다 |
| 2 · 근거 id 서버 검증 | AI는 없는 id를 지어낸다. 서버가 실제 id와 대조해 신뢰도를 강등한다 |
| 3 · 숫자는 AI가 다시 쓰지 않는다 | 금액·기한·장소는 DB 원문 카드로만 나간다 |
| 4 · 사람 승인 | 승격은 운영자 승인 없이 일어나지 않는다 |
| 5 · 신선도 | 6개월 경과 시 "오래된 정보" 배지, 사용자가 갱신 요청 가능 |
| 6 · 신고 | 잘못된 답변 신고 → 노출 보류 → 운영자 검토 |

## 기술 스택

- **프레임워크** Next.js (App Router, TypeScript) — Vercel 배포
- **DB** PostgreSQL (Neon) + Prisma
- **AI** Google AI Studio Gemini API 직접 호출 (무료 티어), 구조화 출력
- **인증** 이메일 + 비밀번호 자체 구현 (bcryptjs + `jose` JWT, httpOnly 쿠키) — 본선 범위
- **테스트** Vitest — 순수 로직만
- **패키지 매니저** npm

무료 티어만으로 지속 운영 가능한 구조입니다 (Vercel Hobby + Neon + Gemini 무료 티어).

## 실행 방법

```bash
npm install
cp .env.local.example .env      # DATABASE_URL, GEMINI_API_KEY 채우기
npx prisma migrate dev
npm run seed
npm run dev
```

`http://localhost:3000` 접속.

### 환경 변수

| 이름 | 설명 |
|---|---|
| `DATABASE_URL` | Neon Postgres 연결 문자열 |
| `GEMINI_API_KEY` | Google AI Studio API 키. **비워둬도 앱은 동작합니다** — 키워드 검색으로 폴백합니다 |
| `GEMINI_MODEL` | 기본값 `gemini-2.5-flash` |

AI는 증강이지 필수 경로가 아닙니다. 할 일 목록·상황 매칭·질문 등록은 전부 AI 없이 동작합니다.

```bash
npm test
```

**상태·판정이 걸린 순수 로직만** 테스트합니다 — 프로필 매칭, D-day 계산, AI 근거 검증, 키워드 검색. UI와 라우트 배선은 수동 확인으로 검증합니다. 해커톤 일정상 전체 커버리지를 목표로 하지 않습니다.

## 시드 데이터 추가 규칙

**확인하지 못한 값은 넣지 않습니다.** 추정으로 채우지 않고 항목 전체를 비워둡니다. 모든 항목은 `sourceNote`(출처와 확인 경로)와 `verifiedAt`(확인 날짜)이 있어야 하고, 없으면 `npm run seed`가 실패합니다.
