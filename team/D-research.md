# D — 데이터 조사 (박용민)

[team/README.md](README.md)를 먼저 읽어주세요.

**맡는 것:** 시드 데이터 조사·검증·입력, 출처 기록
**안 맡는 것:** 코드, 발표(→ 우희태)

조사 결과는 **우희태(B)** 에게 넘기면 `prisma/seed-data.ts` 에 들어갑니다. 발표에 쓸 근거 자료가 필요하면 우희태와 맞춰주세요.

---

## 이 역할이 이 프로젝트의 최대 병목입니다

**코드가 다 돌아가도 보여줄 내용이 없으면 데모가 성립하지 않습니다.**

지금 확인된 할 일은 **3건뿐**입니다 — 전입신고, 확정일자, 전월세신고. 전부 전국 공통 행정 절차입니다. 그런데 이 프로젝트의 차별점은 **"동네마다 다른 생활 정보"** 이고, 그건 **쓰레기 배출 요일·종량제 봉투 판매처·주민센터 전화번호**입니다. 이게 없으면 심사위원 눈에는 그냥 [이사노트](https://isanote.kr/)와 같은 앱으로 보입니다.

**D가 조사해 오는 항목 하나하나가 곧 차별점입니다.**

### 확인하지 못한 값은 넣지 않습니다

추정으로 채우지 말고 **항목 전체를 비워두세요.** 이 제품의 전제가 "정보의 출처는 항상 사람"인데 시드부터 어기면 안 됩니다. **행정 정보가 틀리면 사용자가 실제로 과태료를 냅니다.**

모든 항목은 `sourceNote`(어디서 어떻게 확인했는지)와 `verifiedAt`(확인한 날짜)이 있어야 하고, 없으면 시딩이 아예 실패합니다.

그리고 **이 조사 기록 자체가 심사 점수입니다.** "지역 문제 적합성"에서 통계 인용보다 "직접 조사했다"가 훨씬 세게 먹힙니다.

## 조사 항목

우선순위 순입니다. 위에서부터 하나씩 확정해 B에게 넘기세요.

### 최우선 — 이게 있어야 차별점이 생깁니다

- [ ] **월계1동 쓰레기 배출 요일** — **구역별로 갈리는지 먼저 확인.** 동 전체가 같으면 `/setup`의 구역 선택을 아예 없앱니다 (A에게 알려주세요)
- [ ] **음식물 쓰레기** 배출 방법과 요일
- [ ] **재활용 분리배출** 요일과 방법
- [ ] **종량제 봉투 판매처** — 월계1동 실제 위치 (편의점·마트 이름과 위치)
- [ ] **월계1동 주민센터** 주소와 전화번호 ← 앱의 "전화 걸기" 버튼에 쓰입니다

### 다음

- [ ] **대형폐기물** 신고 절차와 수수료 (노원구 기준)
- [ ] **전입신고 과태료 금액** (기한 14일은 확인됨)
- [ ] **동물등록** 절차·접수처·미등록 과태료 → 조건 `requiresPet: true`
- [ ] **거주자 우선주차** 신청 절차 → 조건 `requiresCar: true`
- [ ] **광운대 기숙사 거주자**의 전입신고 처리 방식 → 조건 `housingTypes: ['DORM']`
- [ ] **아파트 관리사무소가 대행하는 항목** → 조건 `housingTypes: ['APARTMENT']`
- [ ] **월세 세액공제** 신청 방법 → 조건 `contractTypes: ['MONTHLY']`

**아래쪽 다섯 개가 "상황별로 갈린다"를 보여주는 항목입니다.** 시연에서 조건을 바꿔가며 목록이 달라지는 걸 보여주려면 조건이 붙은 항목이 여러 개 필요합니다.

### 조사처

- **노원구청 홈페이지** — 청소행정과, 공지사항, 분야별정보
- **월계1동 주민센터 전화** — 가장 확실합니다. 쓰레기 요일과 봉투 판매처는 전화 한 통이 홈페이지보다 정확합니다
- **정부24 / 찾기쉬운 생활법령정보** — 행정 절차와 기한
- **광운대 생활관 홈페이지 또는 행정실** — 기숙사 전입신고

## 입력 양식

확인된 항목은 아래 양식으로 정리해 B에게 넘기면 `prisma/seed-data.ts`에 들어갑니다.

```ts
{
  title: '',           // 뭘 해야 하나
  why: '',             // 안 하면 어떻게 되나 ← 이게 없으면 사람은 안 합니다
  dueOffsetDays: null, // 이사일 기준 며칠. 이사일 기준이 아니면 null로 두고 howTo에 원문
  howTo: '',           // 절차
  linkUrl: null,
  placeName: null,     // '월계1동 주민센터'
  placeAddress: null,
  placePhone: null,    // 전화 걸기 버튼
  category: 'ADMIN',   // ADMIN | WASTE | HOUSING | LIFE
  housingTypes: [],    // 비우면 전원. 예: ['ONE_ROOM', 'VILLA']
  contractTypes: [],   // 비우면 전원
  requiresCar: false,
  requiresPet: false,
  studentOnly: false,
  sourceNote: '',      // 필수 — 어디서 어떻게 확인했는지
  verifiedAt: new Date('YYYY-MM-DDT00:00:00Z'), // 필수
}
```

**`why`를 대충 쓰지 마세요.** 대부분의 체크리스트가 "무엇을 해야 하는지"만 적고 "안 하면 어떻게 되는지"를 빼먹습니다. 그래서 아무도 안 합니다. **"14일 넘기면 과태료, 보증금 보호를 못 받습니다"** 같은 문장이 이 앱의 실제 값어치입니다.

**기한이 이사일 기준이 아니면 `dueOffsetDays`를 `null`로 두세요.** 예를 들어 전월세신고는 **계약일**로부터 30일인데, 이사일 기준으로 환산하면 틀린 날짜가 나옵니다. 그런 건 `howTo`에 원문 그대로 적습니다.

## 완료 기준

- [ ] 최우선 5개 항목 확정, 출처와 확인 날짜 기록
- [ ] 조건이 붙은 항목(`requiresCar`/`requiresPet`/`housingTypes`) 최소 3개 확보 — 시연에서 목록이 갈리는 걸 보여주려면 필요합니다
- [ ] 우희태에게 넘겨 `npm run seed`가 통과
- [ ] 발표에 인용할 조사 출처 정리 (어디서 어떻게 확인했는지)
